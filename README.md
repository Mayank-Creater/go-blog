# go-blog

A simple static blog engine written in Go. It reads Markdown posts from `content/`, renders HTML using templates, and outputs a static site to `public/`.

## Features

- Markdown content with YAML frontmatter metadata
- Static site generation (`build`)
- Local development server (`serve`) with content watching and automatic rebuilds
- Post scaffolding command (`new`)
- Draft post support (drafts are excluded from builds)
- Embedded static assets for the dev server plus copied project static assets in generated output

## Requirements

- Go (see `go.mod` for the module's Go version)

## Project structure

```text
.
├── content/            # Markdown source posts (*.md)
├── templates/          # HTML templates (base, index, post, partials)
├── static/             # Project static assets copied to public/static during build
├── public/             # Generated site output
├── internal/
│   ├── content/        # Content scanning, parsing, scaffolding
│   ├── render/         # HTML rendering and asset copying
│   └── server/         # Local HTTP dev server
└── main.go             # CLI entrypoint
```

## Getting started

### 1. Create a post

```bash
go run . new -title "My First Post"
```

This creates a Markdown file in `content/` with starter frontmatter.

### 2. Build the site

```bash
go run . build
```

Generated files are written to `public/`.

### 3. Serve locally (with rebuild on content changes)

```bash
go run . serve
```

Default address: `http://localhost:8080`

You can specify a port:

```bash
go run . serve -port :3000
```

`serve` performs an initial build, starts watching `content/` (recursively), and rebuilds automatically when files are created, edited, removed, or renamed.

## CLI usage

```bash
go run . <command> [arguments]
```

### Commands

#### `build`
Performs a full rebuild of the static site.

```bash
go run . build
```

#### `serve`
Builds the site, starts the local HTTP server, and watches `content/` for changes.

```bash
go run . serve [-port :8080]
```

Flags:
- `-port` — address/port for the local server (default: `:8080`)

#### `new`
Creates a new post scaffold in `content/`.

```bash
go run . new -title "Post Title" [-tag "go"] [-draft] [-description "Short summary"] [-cover "/static/cover.png"]
```

Flags:
- `-title` (required) — post title
- `-tag` — tag(s) string used in scaffold frontmatter (default: `new`)
- `-draft` — mark the post as draft (default: `false`)
- `-description` — post description
- `-cover` — cover image path/value

## Post format

Posts are Markdown files in `content/` with YAML frontmatter. Example:

```md
---
title: "My First Post"
date: "2026-11-17"
tags: [go, blog]
draft: false
description: "A short description"
cover: "/static/cover.png"
---

# My First Post

Write your content here.
```

### Notes on metadata/build behavior

- `title`, `date`, `tags`, and `draft` are parsed from frontmatter.
- Posts with `draft: true` are skipped during site generation.
- Posts are sorted by `date` during build.
- Output post filenames are generated by slugifying the post title (e.g. `My First Post` -> `my-first-post.html`).

## Build and output behavior

- `build` and content-triggered rebuilds are **full rebuilds** (all content is rescanned and rendered, and static assets are recopied).
- Generated HTML pages are written to `public/`.
- The homepage is generated as `public/index.html`.
- Project static files from `static/` are copied to `public/static/`.

## Development notes

- The content watcher is currently used in `serve` mode and watches the `content/` directory (recursively).
- If you change templates or files in `static/`, run `build` again (or restart `serve`) to regenerate output, since those paths are not currently watched.
